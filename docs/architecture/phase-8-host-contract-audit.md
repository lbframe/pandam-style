# Phase 8 Vite host contract audit

Status: pre-implementation audit against the Phase 6+7 reconciliation base
`ce6601d8bd02f31f893d0ea386c25874fb2e5011`. This records the public SDK
available before the Vite adapter is implemented. It does not claim that the
adapter or any SDK extension has shipped.

The production authority is `createProjectSession()` from the compiler root
entry. `/host` currently exposes only `readArtifact`, `preparePublication`,
`commitPrepared` and `abortPrepared`. Session methods also expose initialize,
mutation, validation, current state, diagnostics, watcher lifecycle, audit and
close. All calls are Promise-based and serialized by the service.

## Implementation consequences

Three public gaps are confirmed before implementation: the service cannot ingest
a host-provided in-memory source revision; artifact reads omit the source digest
needed to compare host bytes to the exact compiler input; and a clean Vite build
cannot load the generated facade or read the rest of the unpublished canonical
artifact set. The only SDK extensions authorized by this audit are the typed
source-overlay mutation input, `sourceDigest` on `ArtifactResult`, and
`readGeneratedArtifacts(revision)`. They must enter or report from the existing
Project Service queue, preserve exact revision and provenance checks, and
receive focused SDK tests before the Vite adapter uses them.

The adapter will own Vite hook registration, normalized Vite IDs, an isolated
service handle per configured project, stylesheet/HMR transport and output
lifecycle coordination. It will not calculate coverage, CSS, design-system
vocabulary, artifact digests, reuse validity or publication state. A configured
multi-output build and `build.write: false` will be rejected with structured
`PMS_UNSUPPORTED_FEATURE` diagnostics unless a separately tested support path is
added.

The host contract does not authorize a private compiler import. The adapter may
import only `@pandamstyle/compiler` and its public `/host` entry point.
