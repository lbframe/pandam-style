# AG-13.1: distributed surface inventory

Status: **inventory gate (AG-13.1), no product change.** It is the mandatory
removal inventory of [#10](https://github.com/lbframe/pandam-style/issues/10)
(epic [#4](https://github.com/lbframe/pandam-style/issues/4)), made before the
AG-02 transports are finalized. It removes nothing. For every distributed
surface it records one decision: retain, with the agent workflow and evidence,
or remove/replace, with an owning issue and a replacement-before-removal note.
Removal happens in
[AG-13.2 (#32)](https://github.com/lbframe/pandam-style/issues/32); the final
check against release tarballs is
[AG-13.3 (#33)](https://github.com/lbframe/pandam-style/issues/33).

The base is `cbfd48b` (main, after the AG-01.1 design note). The
[accepted plan](agentic-optimizations-plan.md) (AG-13, AG-02) and
[review](agentic-optimizations-review.md) are plans, not shipped APIs. The
[AG-01.1 design note](ag-01.1-operation-registry.md) is reused for the session
and CLI operations; its agent layer is in flight in PR #135.

The same entries are committed as data in
[`ag-13.1-surface-inventory.v1.json`](ag-13.1-surface-inventory.v1.json). It
also holds the observed pack listings and export keys, so a later task can diff
a fresh observation against it. Section 3 presents the same entries; Appendix
A.8 checks that every decided entry carries its evidence or owner.

Evidence labels:

- **observed**: produced by a command or probe run for this inventory (Appendix
  A, B).
- **test**: asserted by an existing test or qualification tool (named, not run
  here unless stated).
- **corpus**: the AG-00 task corpus (`benchmarks/agentic/tasks`, fixtures,
  oracles) or the runner's mounted agent resources.
- **baseline**: the frozen AG-00.3 run records
  (`benchmarks/agentic/baseline/2026-10-21`, 396 run records). These keep final
  reports and breach details, not raw transcripts, so a count is a lower bound.
- **source, unverified**: read in source only, not executed.

## 1. Method

1. **Publication boundary.** `yarn build`, then `npm pack --dry-run --json` in
   each of the five packages (observed). Every packed file is an entry or part
   of a grouped entry. A static import walk from each `exports` target and `bin`
   checked that every shipped JavaScript file is reachable (observed, Appendix
   B.2): none is dead. The only unreachable file is `core/src/types.ts`, which
   the `types` condition references.
2. **Exports.** Each export target was imported and its keys listed (observed,
   Appendix B.2). They match the key sets pinned by
   `tools/pms/package-qualification.js:957-960`.
3. **Executables.** `pms-build` was run on copies of the compiler fixtures
   `valid`, `neg-unknown-token` and a syntax-error variant, plus the no-argument
   and missing-config paths. `pandamstyle-next` was run with rejected arguments.
   The generated output set was listed (observed, Appendix B.1).
4. **Dependencies.** Each direct dependency was searched in `src/` and in the
   built `lib/*.mjs` (observed). The transitive closure comes from the yarn
   workspace resolution (61 packages for the compiler, observed).
5. **Human-facing signatures.** `git grep` over tracked files for output writes,
   log calls, color/TTY/prompt libraries, ANSI escapes, help/format flags, DOM
   and server code, snapshots and CI presentation (Appendix A.4). `git grep` is
   used because `grep` on the runner host is an alias of `ugrep` with different
   `--include` semantics.
6. **Agent need.** Corpus host and check-kind distributions, corpus fixture and
   task references, runner mounts (`runner/src/store.mjs:27-31`) and baseline
   run records (Appendix A.6).
7. **In-flight surfaces.** `gh pr list --state open` and, for each PR, its file
   list and `git show origin/<branch>:<path>` of the relevant files.

Every "does not exist" claim in this document is the empty result of a command
listed in Appendix A.4 or A.7 (section 4 lists them).

## 2. Decision vocabulary

| Decision   | Meaning                                                                                                                                                                                                                        |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| retain     | Kept. The entry names the agent workflow that needs it and the evidence.                                                                                                                                                       |
| retain (…) | Kept for a reason outside the agent-need rule, stated explicitly: `upstream-transitive` (owned by a dependency, not removable without replacing it), `legal` (license notices) or `contributor` (repository-only, not packed). |
| remove     | Deleted by the owner, AG-13.2 (#32). A machine replacement is not needed or already exists; the entry says which.                                                                                                              |
| replace    | The owner issue first delivers the machine replacement; AG-13.2 (#32) then deletes the surface in the documented breaking release (AG-12.4, #37).                                                                              |
| in flight  | A surface of an open PR or planned issue. Recorded, not decided. It enters this inventory when it merges.                                                                                                                      |

## 5. Requirements for transport implementers (AG-02.x)

These bind AG-02.1 to AG-02.6 (#11, #14, #15, #16, #17, #18) before their public
design is final. They restate no AG-01.1 decision; they list what the transports
must not reintroduce and what each removal needs from them.

T1. **One machine response channel.** Each CLI call writes exactly one envelope
(AG-01.1 §3.5) on stdout, for success and for every expected failure. No prose
line, no `PMS_JSON:` prefix, no mixed line. Removes `CLI-pms-build-mixed` and
`CLI-pms-build-success`.

T2. **No human mode.** No `--pretty`, `--format=text`, color, TTY detection,
spinner, progress line or interactive prompt, in any transport or host. Section
4 shows none exists today; none may be added. Compact and detail views are
envelope views, not presentation modes.

T3. **Structured bootstrap failures.** Missing or invalid arguments, a missing
config or definition, a throwing config and a config of the wrong type each
return a coded envelope with a distinct exit code class. Stacks go only to the
bounded technical log channel. Replaces `CLI-pms-build-usage`,
`CLI-pms-build-stack`, `ERR-next-bootstrap`.

T4. **Separate, bounded technical logs.** Logs go to a channel distinct from the
response (stderr or a file), redacted and size-bounded. They are never the only
place an expected failure appears. Replaces `ERR-vite-logger`.

T5. **Do not consume host human channels.** Text rendered by Vite, Next or
Rsbuild (their overlays, terminal output, `compilation.errors`), and
`PmsError.message`, are not protocol. Transports serialize
`PmsError.diagnostics` and session results. Host throws stay (`HOST-vite-throw`,
`HOST-next-errors`); the agent reads the same failure through the owner.

T6. **Replacement map.** Each removal below waits for its replacement:

| Removed surface                                                           | Replacement contract                                            | Owner         |
| ------------------------------------------------------------------------- | --------------------------------------------------------------- | ------------- |
| `pms-build` and `lib/cli.mjs`                                             | AG-02.5 CLI over AG-01 `check` and `publish`, importing the SDK | #17           |
| `formatDiagnostic`                                                        | none: structured diagnostics already exist                      | #32           |
| Vite overlay                                                              | none for removal; dev diagnostics through the attached owner    | #32, then #14 |
| Vite `pandamstyle:diagnostics`, `:revision`, `:transform`, `:performance` | owner status, observation and diagnostics operations            | #14           |
| Rsbuild `onEvent`                                                         | same, Rsbuild owner                                             | #14           |
| Next `onEvent`, `onDiagnostics` (webpack)                                 | Next webpack owner bridge                                       | #15           |
| Next `onEvent`, `onDiagnostics` (Turbopack), `pandamstyle-next` prose     | supervisor agent operations and envelope                        | #16           |
| `TypeError` and uncoded expected errors                                   | AG-01.1 `invalid-input`, `unsupported`, `internal` outcomes     | #8 (PR #135)  |

T7. **Reads never act.** No read or discovery operation imports the config
(`cli.js:29`), stages an audit (`cli.js:125`, `requestFullAudit`) or starts a
watcher (`watch`, AG-01.1 F5). `pms-build` does all three today; the replacement
must separate them into declared effects.

T8. **No browser client for agent operations.** The only browser code that
remains is the Vite CSS revision client (`HOST-vite-client-css`). Agent
operations must not depend on a page being open.

T9. **Keep the envelope off inherited host stdio.** `pandamstyle-next` spawns
Next with `stdio: 'inherit'` (`next/src/cli.js:63-67`), so Next's own output
shares the terminal. The supervisor envelope needs its own channel (file
descriptor, file or bridge), never interleaved with Next's lines.

T10. **Packaging.** No second copy of the compiler in a CLI bundle (the
846,551-byte `lib/cli.mjs` is 36% of the compiler's unpacked size). Agent
tooling dependencies stay out of `@pandamstyle/core` and out of host packages'
runtime closure. A new `@pandamstyle/agent` package has an enumerated file list
and no human onboarding text in its README.

T11. **Keep explanations structured.** `message`, `expected`, `candidates`,
`repair` and examples stay fields; compact views may withhold whole records
(AG-01.1 §3.10) but must not replace them with prose summaries.

T12. **Inventory every new surface.** Each new export, bin, option, file and
dependency introduced by AG-02.x gets an entry with agent evidence in the data
file before release. AG-13.3 diffs the release tarballs against it.

```js
// reach.mjs <repo>: reads the pack listings saved by Appendix A.1
// Static reachability of shipped JS files from package exports + bin.
import fs from 'node:fs';
import path from 'node:path';
const root = process.argv[2];
const pkgs = {
  core: ['src/index.js'],
  vite: ['src/index.js'],
  rsbuild: ['src/index.js'],
  next: [
    'src/index.js',
    'src/adapter.js',
    'src/loader.cjs',
    'src/turbopack-loader.cjs',
    'src/cli.js',
  ],
};
const re =
  /(?:import\s[^'"]*?from\s*|import\s*\(\s*|require\(\s*|export\s[^'"]*?from\s*|import\s*)['"](\.{1,2}\/[^'"]+)['"]/g;
for (const [p, entries] of Object.entries(pkgs)) {
  const dir = path.join(root, 'packages', p);
  const seen = new Set();
  const stack = entries.map((e) => path.join(dir, e));
  while (stack.length) {
    const f = stack.pop();
    if (seen.has(f) || !fs.existsSync(f)) continue;
    seen.add(f);
    for (const m of fs.readFileSync(f, 'utf8').matchAll(re))
      stack.push(path.resolve(path.dirname(f), m[1]));
  }
  const shipped = JSON.parse(fs.readFileSync(`/tmp/ag131/pack-${p}.json`))[0]
    .files.map((x) => x.path)
    .filter((x) => /\.(c|m)?js$|\.ts$/.test(x) && !x.endsWith('.d.ts'));
  const un = shipped.filter((x) => !seen.has(path.join(dir, x)));
  console.log(
    p.padEnd(8),
    'shipped-js',
    shipped.length,
    'unreachable',
    JSON.stringify(un),
  );
}
```

The result is `observed.exports` in the data file. The reachability walk follows
relative `import`, `export … from`, `import()` and `require()` specifiers from
each `exports` target and `bin` of core, vite, rsbuild and next, then compares
them with the packed JavaScript files. Result: no unreachable shipped file
except `core/src/types.ts` (types condition). The compiler's `lib/` entries are
rollup outputs named by `exports` and `bin`, and `lib/compat-data.v1.json` is
read by URL from them.
