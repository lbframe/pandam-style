# Phase 7 authority inventory

Status: implementation inventory for the Project Service authority boundary.
This describes the Phase 7 branch only; it does not claim Phase 6 is complete.

## Production paths

| Path                                                                                                                                                       | Classification                           | Authority boundary                                                                                                                                                                                                                                                                                          |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `packages/compiler/src/api/project.js`                                                                                                                     | **CANONICAL SERVICE**                    | The only production factory for project lifecycle. It owns project/session/revision identities, the per-session operation queue, validation state, ticket state, watcher handles, output leases, and the association to committed generations.                                                              |
| `packages/compiler/src/api/index.js` and the root package export                                                                                           | **CANONICAL SERVICE**                    | Exposes the stable root: `createProjectSession`, `PmsError`, `Codes`, `formatDiagnostic`, and diagnostics ABI constants. Internal graph/session/publication hooks are not added to this entry point.                                                                                                        |
| `packages/compiler/src/project/session/index.js`                                                                                                           | **INTERNAL ALGORITHM CALLED BY SERVICE** | Owns the per-session incremental algorithm: file state, module graph context, coverage graph, design-system views, CSS state, validation, and staged publication inputs. Production calls enter through `api/project.js`; package consumers cannot import this path through the export map.                 |
| `packages/compiler/src/project/mutations/**`, `project/graph/**`, `project/css-state/**`, frontend compilation, and `artifacts/publication/transaction.js` | **INTERNAL ALGORITHM CALLED BY SERVICE** | Implement mutation resolution, positive/negative dependencies, coverage, design-system views, compilation, CSS aggregation, and transactional output. Their state is created or accessed inside one session context. They do not expose a competing service lifecycle.                                      |
| `packages/compiler/src/api/cli.js` and `bin/pms-build.js`                                                                                                  | **CANONICAL SERVICE**                    | The CLI loads inputs, creates one public session, initializes, validates, requests the audit, compiles, formats protocol diagnostics, and closes. It has no graph or publication implementation.                                                                                                            |
| `packages/compiler/src/api/host.js` and `/host`                                                                                                            | **CANONICAL SERVICE**                    | `createHostBridge()` binds only revision-bound artifact read and prepare/commit/abort operations from the supplied public session. It adds no compiler state.                                                                                                                                               |
| `packages/compiler/src/hosts/watcher/**`                                                                                                                   | **INTERNAL ALGORITHM CALLED BY SERVICE** | The watcher is a bounded input journal. It tracks filesystem event evidence (known paths, content digests, a pending burst), not coverage, validity, CSS, registry, or publication state. The public service seeds it from its session and routes transactions and resyncs through queued `applyChanges()`. |

## Global mutable state review

| State                                                                         | Classification                         | Evidence / disposition                                                                                                                                                                                                                                                            |
| ----------------------------------------------------------------------------- | -------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `activePublisherLeases` in `api/project.js`                                   | Service coordination only              | Keys are canonical output paths and values are opaque session IDs. It holds no session, graph, cache, file state, or validity answer; initialization failure and idempotent close release entries. It prevents two live service sessions from publishing to one output directory. |
| `AsyncLocalStorage` singleton in `project/graph/resolution.js`                | Immutable context carrier              | Each incremental session creates a distinct graph context and wraps all internal methods in that context. Context maps are not stored in the singleton. The fallback context is only for private calls outside a session, including oracle/test use.                              |
| `collector`, `engine`, and `workEliminatedFlag` in `observability/metrics.js` | Observability / qualification controls | These select measurement output or a benchmark-only work-elimination mode. They do not decide whether a production artifact is semantically valid. The work-elimination flag is read once from the process environment.                                                           |
| `globalThis.__PMS_PARSE_OWNER__`                                              | Observability only                     | A synchronous parse label used by the external parser hook. The previous value is restored in `finally`; it carries no compiler decision.                                                                                                                                         |
| `hardlinkSupport` in publication                                              | Output optimization capability         | A process-wide probe selects hard-link reuse or copy fallback. Link failures also fall back to copy. It cannot change published bytes or the committed artifact set.                                                                                                              |
| Static policy tables, frozen mode/ABI lists, and private lookup tables        | Immutable module constants             | They describe compiler policy and are not keyed by a project or mutated as a build runs. Per-build derivations are in session-owned state.                                                                                                                                        |

All semantic maps that survive a call—file states, resolution keys and negative
answers, module overlays, relay answers, coverage graphs, CSS state, and
generated-artifact authentication—are created inside a session context. Closing
the service clears the incremental session structures and drops the service's
references. The only process-wide service registry is the output lease map
described above; it does not retain semantic truth.

## Production consumers found

The compiler source search found one production service construction site in the
CLI, plus the Project Service's private construction of the synchronous
incremental owner. Direct `buildProject`, fresh-session, Vite-seam, and
low-level-session calls are confined to tests, semantic qualification,
benchmarks, and `tools/pilot`. No shipped agent host, Vite adapter, or Next
adapter remains as an alternate authority.

The low-level owner's underscored `_designSystemIdentity`,
`_candidateTokenEntries`, `_artifactFor`, `_cssForCurrentRevision`, and
`_publicationCandidateDigest` methods are **required internal service seams**.
They return immutable projections or digests to `api/project.js`; no
implementation object or mutable graph/cache object is returned to a caller or
exported from the package root. Their only external use is the private
inspection bundle used by qualification tests.
