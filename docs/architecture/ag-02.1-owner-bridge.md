[#11](https://github.com/lbframe/pandam-style/issues/11) (epic

### 1.3 The output lease

`acquireProcessOutputLease(outDir)` (`api/output-lease.js`) listens on a Linux
abstract Unix socket. Other platforms use TCP on `127.0.0.1`. `project.js` adds
an in-process map keyed by the same canonical `outDir`.

| Fact                                                                                                                                                                                                                                                                                                        | Evidence                                                                                                      |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| The name is `\0pandamstyle-output-` + SHA-256 of the canonical `outDir`. The new entry in `/proc/net/unix` equals that name                                                                                                                                                                                 | observed, P1.1–P1.3                                                                                           |
| `/proc/net/unix` is mode `444`: every local user can list the name                                                                                                                                                                                                                                          | observed, P1.4                                                                                                |
| A second owner in another process fails `PMS_INVALID_REVISION`, `reason: output-owned`, `filesystemCode: EADDRINUSE`                                                                                                                                                                                        | observed, P1.5                                                                                                |
| A second owner in the probe's own process fails the same way: the in-process map is per process, the OS lease decides                                                                                                                                                                                       | observed, P1.6                                                                                                |
| A client that connects and writes a request is accepted, then closed by the peer after 3 ms with **0 bytes** received. The owner keeps exclusivity                                                                                                                                                          | observed, P1.7–P1.8                                                                                           |
| After `SIGKILL` of the owner, a new process acquires the lease at once. The name disappears with the last holder                                                                                                                                                                                            | observed, P1.9–P1.10                                                                                          |
| Abstract sockets have no filesystem permission check: any process in the same network namespace can connect                                                                                                                                                                                                 | `unix(7)`; not probed with a second user (none available)                                                     |
| The name is per network namespace. Two owners in different namespaces (for example two containers sharing a bind-mounted project) would both acquire it                                                                                                                                                     | `network_namespaces(7)`; **unverified**: `unshare -rn` is not permitted on this machine                       |
| On other platforms the port is `10000 + (hash mod 20000)`: two projects can collide, and any local user can bind the port first                                                                                                                                                                             | source, unverified                                                                                            |
| **The key is computed once, when the session is created.** An owner whose `outDir` did not exist yet keeps the literal path as its key. If that path later becomes a symlink, a second owner configured with the target directory gets another key. Both owners then hold a lease on one physical directory | observed, P1.11–P1.12. A third owner configured with the link path, after the link exists, is refused (P1.13) |

The lease has no data handler and no protocol: it is exclusion only. Deliverable
2 of #11 is therefore a property to keep, not a change to make.

### 1.6 Socket facts the design depends on

All observed (P4), on Linux with a pathname `AF_UNIX` stream socket.

| #   | Fact                                                                                                                                                                                                                                      |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S1  | The socket file mode follows the umask: `775` under `002`, `777` under `000`, `700` under `077`. A socket created under this machine's default umask (`002`) is group-connectable unless its directory forbids it                         |
| S2  | `listen('/proc/self/fd/<dirfd>/name')` creates the socket in the directory the descriptor holds. `connect` through the same form works                                                                                                    |
| S3  | **libuv silently truncates socket paths to 108 bytes.** A 200-byte path listens "successfully" on the truncated name, and `connect` to the long path also reaches it. Two long names with a common 108-byte prefix would share one socket |
| S4  | After `SIGKILL`, the socket file remains. `connect` gives `ECONNREFUSED`; `listen` gives `EADDRINUSE` until the file is unlinked                                                                                                          |
| S5  | `listen` on a name occupied by a planted symlink gives `EADDRINUSE`; the symlink target is untouched                                                                                                                                      |
| S6  | After the anchored directory is renamed and replaced by a symlink, an anchored `listen` lands in the renamed directory, not in the symlink target; an anchored `connect` still reaches the first socket                                   |
| S7  | `mkdir(…, { mode: 0o700 })` under umask `002` gives `700`; `mkdtemp` gives `700`                                                                                                                                                          |
| S8  | `$XDG_RUNTIME_DIR` is `/run/user/1000`: mode `700`, owned by the user, `tmpfs`                                                                                                                                                            |
| S9  | `open(O_CREAT \| O_EXCL \| O_NOFOLLOW, 0o600)` under umask `002` gives `600`. On a planted symlink it fails `EEXIST`; a reader with `O_NOFOLLOW` fails `ELOOP`                                                                            |

Node exposes no `SO_PEERCRED`, so the server cannot read the peer's uid (source:
the `net` API). The precedent for Linux-specific anchoring is AG-01.2 §3.8.

### 1.7 The agent layer the bridge reuses

- `createAgentBinding({ session })` is the only minting point.
  `binding.dispatch(request, { capability, signal })` never throws and returns
  an envelope. Capabilities are frozen objects whose authority is a
  module-private `WeakMap` entry. They cannot cross a process boundary by
  construction (`agent/capabilities.js`).
- `snapshotRequest` enforces 65 536 request bytes, depth 16, 4 096-byte strings
  and 512-item arrays before any schema walk (`agent/snapshot.js`). Responses
  are capped at 262 144 bytes (compact) and 2 097 152 bytes (detail)
  (`agent/registry.js:189-203`).
- The closed outcome set has 8 members (`protocol/envelope.js:43-52`). The
  registry pre-writes `discover`, `session.open` and `session.attach` as planned
  entries owned by #11. Their contracts use
  `unsupported-capability: owner-absent` and `stale-revision: descriptor-stale`
  (`agent/registry.js:580-904`).
- Session hooks run as one queued step on the session's queue
  (`project.js:1274-1279`). P7 interleaved, 20 times, a host edit, a
  `preparePublication`, an agent `check` and a `commitPrepared`. All 20 host
  commits succeeded. 20 checks of the current revision succeeded, and 20 checks
  of the previous revision returned `stale-revision` (observed).
- After the host calls `session.close()`, the binding answers
  `denied-access: revoked` (observed, P7). That is correct in process, but a
  remote client must not see it as an authority decision (§3.12).

### 1.8 Findings the design must absorb

- **B1.** The lease is an abstract socket: listable by every user, connectable
  without a permission check, scoped to a network namespace (§1.3). Reusing it
  or its mechanism as an endpoint would expose the endpoint to every local user.
- **B2.** The lease key can split on a symlink created after a session started
  (§1.3). Two owners then write one directory. This is a **pre-existing** defect
  of the lease. #11 keeps the lease's semantics unchanged, so the defect is
  recorded as a follow-up (§7).
- **B3.** Any in-project location can advance a session's revision (§1.5). A
  descriptor written there would revoke the host's publication tickets.
- **B4.** Socket paths over 108 bytes are silently truncated (S3).
- **B5.** The socket file mode follows the umask (S1). Access control cannot
  rely on the socket file mode.
- **B6.** The Turbopack supervisor's credential lives inside the project tree,
  where version-control and indexing tools see it (this repository's own
  `.gitignore` does not list it, P5.6), and is sent as a bearer token in every
  frame. A credential file naming another socket makes the client send the token
  to that socket (observed, P5.3). Writing that file needs the user's own uid.
  This is input for #16, not changed here.
- **B7.** After `session.close()`, the binding returns `denied-access: revoked`
  (§1.7).
- **B8.** The pre-written contracts map an absent owner to
  `unsupported-capability`, whose retry hint is `never`. #11 and the plan
  require `owner-required` (§3.12).

## 2. Threat model

**Adversary.** An agent client process on the same machine. It controls its
request bytes and everything it can write: the project, its caches, the runtime
directory of its own uid, the descriptor and key files of its own uid, and other
sockets. It can connect, disconnect, replay, race and flood.

**Trusted.** The host process that owns the session, and code it loads on
purpose. This is the AG-01.1 boundary, unchanged.

**The uid boundary.** A process running under the host's uid can read the host's
files and, depending on `ptrace` policy, its memory. **Nothing inside one uid is
a secret from another process of that uid.** The bridge does not claim to
separate two processes of one uid. Its access control separates uids. Its
capability control limits what the host exposes to any connection. That is the
epic's statement: "This boundary does not pretend to sandbox arbitrary external
filesystem access."

**Assets.** Publication authority (one writer per output directory), host-issued
capabilities, revision and session identity, the host's CPU, memory and file
descriptors, and the meaning of outcomes.

| #   | Threat                                                                                                                   | Required property                                                                                                                                                                                    |
| --- | ------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1  | Another uid connects to the endpoint or reads the credential                                                             | The endpoint and key live in a directory that only the owner's uid can traverse. The check is made on the opened directory, not on a path                                                            |
| A2  | A forged descriptor redirects a client to another endpoint (another project's owner, another service, a spy)             | The client never connects to a path taken from the descriptor. The endpoint name is derived from the project identity; a descriptor naming anything else is invalid                                  |
| A3  | A stale descriptor or socket from a dead owner                                                                           | Liveness is proved by the handshake, never inferred from a file. A dead owner is `owner-required: owner-unreachable`. Only the next owner of the same name, under the lease, removes the stale files |
| A4  | Endpoint impersonation: something else listens at the endpoint                                                           | The owner proves knowledge of the session key before the client sends anything derived from it. The key never crosses the wire                                                                       |
| A5  | A client self-assigns capabilities (`grants`, `role`, `capability` fields in the handshake or the request)               | Capabilities are minted on the owner side, per connection, from the host's configuration only. Handshake and request schemas are closed; such fields are `invalid-input`                             |
| A6  | Replay of a captured handshake or request                                                                                | Both sides contribute a fresh nonce to each handshake. A request is valid only on its authenticated connection, at its sequence number                                                               |
| A7  | Oversized, malformed, deep, pipelined, slow or incompatible-protocol input                                               | Every frame is bounded before it is buffered. Handshake frames have their own small bound and a deadline. Every failure is a structured error. An unparseable frame closes the connection            |
| A8  | A second writer: a standalone owner racing an attached host, or a failed attachment that falls back to opening a session | Only an explicit `session.open` creates an owner, and it acquires the normal lease. The attach path has no code that creates a session                                                               |
| A9  | Discovery executes config or launches a compiler                                                                         | `discover` and `session.attach` read files as data and import no project module. A structural test bounds their import graph                                                                         |
| A10 | Permission and umask mistakes (S1)                                                                                       | Directory `0700` is checked on the opened descriptor. Files are created `0600` with `O_EXCL`; the socket's own mode is not relied on                                                                 |
| A11 | Symlink and TOCTOU on the runtime directory, the descriptor, the key and the socket                                      | All file operations are anchored on a directory descriptor (`/proc/self/fd/<fd>/<name>`) with `O_NOFOLLOW`, as in AG-01.2 §3.8. Platforms without anchoring fail closed                              |
| A12 | Shutdown and reconnect: a client keeps talking to a new session as if it were the old one                                | The key and the session identity change with every owner start, and the handshake proves both. A changed session is `stale-revision: session-changed`, never a silent continuation                   |
| A13 | Descriptor pollution of canonical artifacts or watchers (B3)                                                             | Descriptor, key and socket live outside the project tree                                                                                                                                             |
| A14 | Response misattribution: an error for one frame read as the answer to the next request                                   | Every response carries the request's connection sequence number. A frame that cannot be correlated closes the connection                                                                             |
| A15 | Outcome ambiguity: "no owner" read as "unsupported, never retry", or as an authority decision (B7, B8)                   | A distinct `owner-required` outcome with closed reasons. Connection-level failures never surface as `denied-access` unless authentication failed                                                     |
| A16 | Resource exhaustion through connections                                                                                  | A fixed connection limit, one request in flight per connection, and reads paused while a request runs                                                                                                |

Out of scope: separating processes of one uid (stated above); fairness between
clients and long-session expiry (AG-10.1); MCP and CLI transports (AG-02.5,
AG-02.6); host registration (#14, #15, #16).

## 3. Design

### 3.1 Layering and location

```
packages/compiler/src/agent/bridge/runtime-dir.js   runtime directory: location, checks, anchoring
packages/compiler/src/agent/bridge/descriptor.js    names, descriptor and key: write, read, clean
packages/compiler/src/agent/bridge/frames.js        framing and limits
packages/compiler/src/agent/bridge/handshake.js     transcript and proofs
packages/compiler/src/agent/bridge/server.js        startOwnerBridge (owner side)
packages/compiler/src/agent/bridge/client.js        connect, handshake, forward (client side)
packages/compiler/src/agent/workspace.js            createWorkspaceBinding (sessionless binding)
```

The issue lists `packages/compiler/src/api/` as the starting point. The bridge
goes under `src/agent/` instead. AG-01.1 §3.1 fixes the dependency direction:
`agent/` imports `api/`, and nothing under `api/` imports `agent/`. A bridge in
`api/` must import `binding.js`, which would break that rule. The issue allows
new paths ("new paths are proposed").

PR 1 adds **no package export and no Rollup entry**, as AG-01.1 and AG-01.2 did.
Tests reach the bridge from source and from the private inspection bundle. Hosts
need a published entry to register (#14, #15, #16). That entry must be a
separate Rollup input (`lib/agent.mjs`, AG-01.1 §3.1), loaded by a host only
when its bridge is enabled. The first issue that needs it adds it (§7).

`output-lease.js`, `project.js` and every file reachable from `lib/index.mjs`,
`lib/cli.mjs` and `lib/host.mjs` are unchanged (§5.3).

### 3.2 Transport and local access control

**Decision: a pathname `AF_UNIX` stream socket inside a per-user runtime
directory of mode `0700`, bound and connected through an anchored path.** The
output lease is not touched and carries no data.

Checked against the threat model:

- **A1.** The kernel checks search permission on every directory of the path
  before `connect`. A `0700` directory owned by the user closes the endpoint to
  other uids, whatever the socket file mode (A10, S1). This is the mechanism the
  supervisor already uses (§1.4). It was not probed with a second uid (none
  available); it is kernel semantics (`path_resolution(7)`, `unix(7)`).
- **A11.** `/proc/self/fd/<fd>/<name>` binds and connects in the directory
  object the descriptor holds, even after a swap (S2, S6). It also makes the
  path short, which removes the truncation of B4 (S3).
- **B4.** Names are fixed-length (§3.4). The anchored path is at most
  `/proc/self/fd/` + 10 digits + `/` + 38 characters (`N.sock`).

Rejected alternatives:

| Alternative                                   | Why not                                                                                                                                |
| --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| The output-lease socket                       | Deliverable 2 forbids it. It would also turn an exclusion primitive into a protocol surface                                            |
| A second abstract socket                      | No permission check, name listable by every user (B1). Access control would rest on the key alone, with the endpoint open to every uid |
| TCP on loopback                               | Any local user can connect, or bind the port first and impersonate the owner. Port allocation must also be published                   |
| A socket path in the project tree             | Watcher pollution (B3), and the path length depends on the project location (B4)                                                       |
| Bearer token per frame (supervisor precedent) | The token goes to whatever endpoint the client reaches (B6). It authenticates the client only, never the owner                         |
| Peer-credential check                         | Node exposes no `SO_PEERCRED`. A native addon is a new dependency, and the check would add nothing inside one uid                      |

**Platforms.** PR 1 enables the bridge on Linux only, where anchoring was
observed. Elsewhere `startOwnerBridge` and `session.attach` return
`unsupported-capability` with `failure.capability: 'feature:owner-bridge'` and
reason `anchoring-unavailable`, as AG-01.2 does for anchored audit I/O. The host
keeps running without a bridge; no fallback is attempted. macOS (directory
permissions apply, no `/proc/self/fd`) and Windows (named pipes) are follow-ups
that need their own anchoring design and qualification (§7).

### 3.3 Runtime directory

The owner and the client resolve the same location independently:

1. `$XDG_RUNTIME_DIR/pandamstyle`, when `XDG_RUNTIME_DIR` is set and absolute;
2. otherwise `os.tmpdir()/pandamstyle-<uid>`.

The client checks both locations, in this order. A trusted in-process caller
(tests) may pass `runtimeDir` explicitly. There is no environment-variable
override: the owner's environment belongs to the operator, and the client's
choice cannot affect the owner.

Opening the directory (owner and client):

1. `mkdir(dir, 0o700)`; `EEXIST` is accepted (owner only; a client never creates
   it).
2. `open(dir, O_RDONLY | O_DIRECTORY | O_NOFOLLOW)`. A symlink fails here
   (`ENOTDIR` on Linux, model M11).
3. `fstat` on the descriptor: a directory, owned by `process.getuid()`, with
   `mode & 0o077 === 0`. Otherwise the directory is refused with reason
   `runtime-dir-unsafe`.
4. The anchor check of AG-01.2 §3.8: `fstat(fd)` equals
   `stat('/proc/self/fd/<fd>')`. Otherwise `anchoring-unavailable`.

A refusal fails closed. The owner runs without a bridge and reports why to the
host. The client reports `owner-required` with reason `owner-absent`, because no
usable owner is advertised.

Every later step uses `/proc/self/fd/<fd>/<name>` with a single component. The
owner holds the descriptor until the bridge closes.

A user who squats `/tmp/pandamstyle-<uid>` (another uid creating it first) makes
the check fail. That denies the bridge, never grants access; it is stated as a
residual (§6). `$XDG_RUNTIME_DIR` is per user and is preferred for this reason.

### 3.4 Names, descriptor and key

**Name.** `N = h(rootDir) + '-' + h(outDir)`, where `h` is the first 16
hexadecimal characters of SHA-256 over the session's canonical path. `outDir` is
the lease key, so there is at most one advertised owner per lease. The owner
takes both paths from the session, through its binding (`paths()`, §7), never
from the host's options.

The owner writes three entries: `N.key`, `N.sock` and `N.json`.

**Key file `N.key`** (`0600`): 32 random bytes in base64. It is the credential.
A new key is drawn every time a bridge starts. It is never sent on the wire,
never logged and never echoed in a response.

**Descriptor `N.json`** (`0600`): discovery data, **not** a credential. A
descriptor alone authorizes nothing; it contains no secret.

```js
{
  format: 'pandamstyle-owner-descriptor', formatVersion: 1,
  bridgeVersions: [1],              // framing and handshake
  protocolVersions: [1],            // AG-01.1 envelope protocol
  projectId, sessionId,             // the owner session
  rootDir, outDir,                  // canonical; h() of each must equal N
  endpoint: 'N.sock',               // must equal the derived name
  keyId,                            // first 16 hex of SHA-256 of the key text
  owner: { kind: 'attached', host: 'vite' | 'rsbuild' | 'next-webpack'
           | 'next-turbopack' | 'test', pid },
  compilerVersion, createdAt,
}
```

The client validates it with the AG-01.1 schema subset (`schema.js`), as a
closed object with bounded strings (`BOUNDS.rootDir`, `BOUNDS.outDir`,
`BOUNDS.projectId`). It reads at most 8 KiB, through `O_NOFOLLOW`, from a
regular file owned by the user. A descriptor whose names do not hash to `N`, or
whose `endpoint` is not `N.sock`, is `descriptor-invalid` (A2; model M3). The
client never puts descriptor values in envelope `identities`: those come only
from the authenticated owner (AG-01.1 T5).

**Writes.** Each file is created as `N.<ext>.<random>.tmp` with
`O_WRONLY | O_CREAT | O_EXCL | O_NOFOLLOW` and mode `0600`, written, `fsync`ed,
then renamed onto its name, all anchored. A planted symlink at a temporary name
fails `EEXIST` (S9).

**Order of a start.** It runs only after `session.initialize()` has resolved, so
the lease is held:

1. remove stale `N.json`, `N.key` and `N.sock` (own name only);
2. write `N.key`;
3. `listen` on `N.sock`;
4. write `N.json`.

**Order of a stop.**

1. remove `N.json`, then `N.key`;
2. stop accepting connections and destroy open ones; in-flight requests are
   aborted (§3.6);
3. close the listener and remove `N.sock`;
4. dispose the bridge's own binding (§3.7), which revokes every connection's
   capability;
5. the host then calls `session.close()`, which releases the lease.

A descriptor therefore exists only while its writer holds the lease, except
after a crash.

**Stale entries.**

- After a crash (`SIGKILL`) the three files remain (S4; model M9a). A client
  reading them gets `owner-required: owner-unreachable` from the failed
  connection. It never deletes them: a client is not the lease holder, and a
  delete could race a new owner's fresh descriptor.
- The next owner of the same name removes them in step 1 of its start. It holds
  the lease for that `outDir`, so no other live owner can own that name.
- Entries of names that no owner restarts remain until the runtime directory is
  cleared (`tmpfs`, at logout or reboot). Removing another name's entries would
  need the liveness check above, which races a starting owner. The residual is
  stated in §6.

A crashed owner may also leave its descriptor while a new owner of the same name
is between step 1 and step 4. The client then sees a missing file or a `keyId`
that does not match the key (`stale-revision: descriptor-stale`, model M2a). It
retries once after re-reading, then reports the outcome.

**Process exit.** The owner registers a `process.once('exit')` handler that
removes its own three entries synchronously. `close()` removes the handler.
Signals that bypass `exit` leave stale entries, handled as above.

### 3.5 Handshake

The goal is mutual proof of the session key, bound to the session identity, with
fresh nonces on both sides. The secret never crosses the wire.

```
client → owner  hello      { t: 'hello', bridge: [1], cn }                      cn: 32 random bytes, base64
owner  → client challenge  { t: 'challenge', bridge: 1, sn, sessionId, proof: Ps } sn: 32 random bytes
client → owner  auth       { t: 'auth', proof: Pc }
owner  → client ready      { t: 'ready', identities, grants, limits }

Ps = HMAC-SHA256(key, 'pandamstyle-owner-bridge/1|server|' + N + '|' + cn + '|' + sn + '|' + sessionId)
Pc = HMAC-SHA256(key, 'pandamstyle-owner-bridge/1|client|' + N + '|' + cn + '|' + sn + '|' + sessionId)
```

- The client verifies `Ps`, in constant time, **before** it sends `Pc`. It also
  checks that `sessionId` equals the descriptor's. An endpoint that cannot prove
  the key learns nothing derived from it (A4; model M2b:
  `denied-access: endpoint-unauthenticated`).
- The owner verifies `Pc` in constant time. On failure it sends
  `{ t: 'error', outcome: 'denied-access', reason: 'authentication-failed' }`
  and closes (model M2c).
- The roles are separated by a domain label, and both nonces appear in both
  proofs. A captured `auth` frame is useless on another connection: the owner's
  nonce differs (A6; model M5).
- `hello`, `challenge`, `auth` and `ready` are closed objects. Any other field,
  `grants` or `role` included, is `invalid-input: malformed-handshake` (A5).
- Each handshake frame is at most 1 024 bytes, and the handshake must complete
  within 2 000 ms of `accept` (A7; model M6, M8).
- A `bridge` list without `1` is `unsupported-capability: protocol-version`
  (model M10). The client checks the descriptor's `bridgeVersions` and
  `protocolVersions` before connecting.
- `ready.identities` is the binding's `session.status` identities (AG-01.1
  §3.5), produced through the binding (§3.8). `ready.grants` lists what the host
  configured (§3.7).

**Who holds the key.** Any process of the owner's uid can read `N.key`. The
handshake does not separate those processes (§2). It does three things:

- it adds a second barrier to the directory permission against other uids;
- it authenticates the owner to the client;
- it binds each connection to one session key, so an owner restart is always
  detected (A12).

**Rotation.** The key lives as long as one bridge. Every bridge start draws a
new key; a new owner session also brings a new `sessionId`. There is no rotation
within one bridge and no expiry; expiry belongs to AG-10.1.

### 3.6 Frames, bounds and cancellation

A frame is a 4-byte big-endian unsigned length followed by that many bytes of
UTF-8 JSON. The length is checked as soon as the 4 bytes arrive, before the body
is buffered.

| Bound                             | Value                                                   | On violation                                                          |
| --------------------------------- | ------------------------------------------------------- | --------------------------------------------------------------------- |
| Handshake frame                   | 1 024 bytes                                             | error frame `invalid-input: request-too-large`, then close            |
| Handshake deadline                | 2 000 ms                                                | close                                                                 |
| Request frame                     | `registry.request.maxRequestBytes` (65 536) + 256 bytes | error frame `invalid-input: request-too-large`, then close (model M6) |
| Response frame (client side)      | the detail `maxResponseBytes` (2 097 152) + 256 bytes   | client closes; the agent gets `internal-error: owner-protocol-error`  |
| Connections per bridge            | 32                                                      | error frame `owner-required: owner-busy`, then close                  |
| Requests in flight per connection | 1                                                       | reads are paused while a request runs                                 |

The 256 bytes cover the frame wrapper. `snapshotRequest` then applies the
AG-01.1 limits to the request itself, unchanged.

After `ready`, the client sends `{ t: 'request', seq, request }`. `seq` starts
at 1 and increases by 1. The owner answers `{ t: 'response', seq, envelope }`.

- A frame that does not parse as JSON, has another type, or has the wrong `seq`
  gets an error frame with `reason: 'malformed-frame'` and the connection is
  closed. Such a frame cannot be correlated with a request, so it is never
  answered as if it were one (A14). The model first answered unparseable frames
  in place and a client read that error as the answer to its next request; the
  close rule fixed it (model M7).
- A request that parses but is invalid for the protocol is answered by
  `binding.dispatch` with an envelope, and the connection stays open. The
  meaning is AG-01.1's, unchanged.
- An error frame is minimal:
  `{ t: 'error', seq: <seq or null>, outcome, reason }`. The client turns it
  into a full envelope with `buildEnvelope` from `envelope.js`, so an agent sees
  one envelope shape (§3.12).

**Cancellation.** Each request gets an `AbortSignal` that fires when its
connection closes. AG-01.1's `before-start` semantics then apply: a queued
request that has not started is `cancelled` with no effect; a started request
completes and its response is dropped. Explicit per-request cancel frames would
require reading while a request runs. They are deferred to AG-10.1.

### 3.7 Capabilities for bridge connections

```js
const bridge = await startOwnerBridge({
  session, // the host's ProjectSession, already initialized
  host: 'vite', // closed list, recorded in the descriptor
  grants: ['consult'], // default; the host's decision, never the client's
});
```

The bridge creates its **own** binding over the session
(`createAgentBinding({ session, initialize: false })`). Disposing it at stop
therefore never revokes a binding that the host uses in process. A session that
is not initialized, or already closed, is refused at start (`TypeError`).

- After a successful handshake, the owner mints one capability per connection:
  `binding.mintCapability({ grants })`. It is kept in the connection's closure
  and passed out-of-band to `binding.dispatch` for every request on that
  connection. It never leaves the owner process (A5).
- `grants` must contain `consult`, because the handshake itself dispatches
  `session.status` (§3.8). It may add `publish`, `mutate-sources`,
  `extend-design-system` and `materialize-audit`. `load-config` and
  `manage-session` are refused at start (`TypeError`): they act on the owner's
  lifecycle, which belongs to the host.
- A client cannot ask for more. It cannot ask for less either in PR 1; a
  narrowing request is a possible later addition, not a need of #11.
- A connection's capability becomes unreachable when the connection closes. All
  capabilities are revoked when the bridge disposes its binding (AG-01.1 §3.4).

**What a grant over the bridge means.** Every process of the host's uid can read
the key, so a write grant on the bridge is a write grant for every such process.
The default is `consult`. Enabling more is the host's explicit configuration:
#14, #15 and #16 decide how a host exposes that choice. An agent that edits the
host configuration to widen it is outside the boundary, as AG-01.1 §6 states for
`vite.config.ts`.

### 3.8 One dispatch path, and version skew

The owner side calls exactly one agent-layer function:
`binding.dispatch(request, { capability, signal })`. `server.js` imports no
handler, no `api/project.js` and no session hook. A structural test enforces
this (§5). Attached requests therefore take the same path as in-process
requests: capability check, schema, preconditions, the session's queue, the same
validation and the same publication authority (AC1; AC5 of #8).

`ready.identities` is produced by dispatching `session.status` through the
connection's capability, not by reading the session directly.

The client and the owner may run different compiler versions: an agent's tool
against a project's installed compiler. The owner's registry is authoritative
for its session. The client forwards each session-bound request **unvalidated**,
apart from the frame bound, and returns the owner's envelope **unchanged**. When
a subject is attached, `protocol.operations` is forwarded too, so the agent sees
the owner's operations. The descriptor records `compilerVersion` for diagnosis
only.

### 3.9 The client: workspace binding, attach and reconnect

```js
const workspace = createWorkspaceBinding({ projectDir }); // trusted tooling, AG-02.5
const capability = workspace.mintCapability({ grants: ['consult'] });
await workspace.dispatch(
  {
    protocolVersion: 1,
    operation: 'session.attach',
    input: { protocolVersions: [1] },
  },
  { capability },
);
await workspace.dispatch(
  { protocolVersion: 1, operation: 'check', input: { rev } },
  { capability },
);
```

`createWorkspaceBinding` is the sessionless counterpart of `createAgentBinding`.
It shares the same `dispatchSafely` core: PR 1 factors it out of `binding.js`,
with no behavior change for the host binding. Its holder is the agent's own
tooling (the CLI and MCP processes of AG-02.5 and AG-02.6). That holder has
exactly the agent's own authority, so minting there grants nothing the agent
does not already have.

Routing, decided by operation and current subject:

| Operation                                    | No subject                                                     | Attached subject                                                  |
| -------------------------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------- |
| `session.attach`, `discover`, `session.open` | local                                                          | local (`session.attach` replaces the subject)                     |
| `protocol.operations`                        | local registry                                                 | forwarded                                                         |
| any other implemented or planned operation   | steps 1–4 of AG-01.1 §3.4, then `owner-required: owner-absent` | forwarded unvalidated; the owner's envelope is returned unchanged |

The local capability check for a forwarded request is `consult`: the tooling's
permission to talk to an owner at all. The owner's capability decides what the
operation may do.

**`session.attach`.** Input: `{ projectId?, outDir?, protocolVersions }`, a
closed object. `outDir` is a project-relative path.

1. Canonicalize `projectDir`, then list the runtime directory: at most 1 024
   entries, through the anchored descriptor. Select names whose prefix is `h()`
   of `projectDir` or one of its ancestors.
2. Read and validate each candidate descriptor. Filter by `projectId` and
   `outDir` when given. Several candidates are `invalid-input: owner-ambiguous`;
   the response lists their `rootDir` and `outDir`, which come from the
   descriptors and are labelled unverified.
3. Read `N.key` (at most 256 bytes, `O_NOFOLLOW`) and check `keyId`.
4. Connect to the anchored `N.sock` and run the handshake.
5. On success, the subject becomes this connection. The result returns the
   owner's identities, from `ready`, and the granted list.

The registry entry becomes `implemented`, with the corrected contract of §3.12.

**Reconnect.** When the connection closes, the subject keeps the last
`sessionId` and becomes "detached". The next session-bound request returns
`owner-required: owner-closed`. A new `session.attach`:

- for the same `sessionId` (the owner's bridge restarted within one session,
  which PR 1 does not do but a host might), continues;
- for a different `sessionId`, succeeds, and the result carries
  `previousSessionId`. Every request still carrying a revision of the old
  session is answered by the client with `stale-revision: session-changed`,
  before forwarding (model M9b). Without this, the owner would see a foreign
  session and answer `invalid-input: foreign-identity`, which blames the agent's
  request for an owner restart.

**No fallback writer.** `client.js` and `workspace.js` do not import
`api/project.js`, `createProjectSession` or the lease. A failed attach returns
an outcome; nothing in that path can create a session (A8; enforced by the
import test of §5). Only `session.open` creates an owner, and it is loaded
lazily in a separate module (§3.10).

### 3.10 Attached and standalone modes

**Attached.** The host owns the session and calls `startOwnerBridge` after
`initialize()` resolves, and `bridge.close()` before `session.close()` (§3.4).
In PR 1 the hosts are a test host in process and a child-process test host. #14,
#15 and #16 register Vite, Rsbuild and the two Next owners.

If a host closes the session before the bridge, an in-flight request is answered
`denied-access: revoked` by the binding (B7). The bridge removes that ambiguity
by construction: it disposes its own binding in step 4 of its stop, and every
request reaching it after its binding's `revoked()` turns true (session closed,
or binding disposed) is answered on the owner side with an error frame
`owner-required: owner-closed`. A structural assertion in the test host checks
the documented order.

**Standalone.** An owner that the agent's own process opens, explicitly:
`session.open` with `{ config, mode: 'standalone' }` on a workspace binding,
under a `load-config` capability. The tooling mints that grant only when the
task asked for standalone ownership: the AG-02.5 CLI flag, or an SDK call that
names it. That is "configuration loaded only under task authority". The config
is agent-writable, and executing it in the agent's own process grants no
privilege the agent lacks. The grant makes the effect explicit and declared.

Sequence:

1. Before executing anything, look for an advertised owner of `projectDir`, as
   in `session.attach` steps 1–4. If one completes the handshake, return
   `denied-access: owner-present` with a `references` entry to `session.attach`,
   and execute nothing. An unreachable or invalid descriptor does not block.
2. Load the config file (project-relative, regular file, inside `projectDir`)
   and its definition with the semantics of `pms-build`'s loader
   (`cli.js:28-31`): one `import()` each, call it if it is a function, require a
   plain object. `cli.js` itself is not touched. A cache-busting query keeps
   edits visible across opens in one process, at the cost of one module instance
   per explicit open.
3. `createProjectSession`, then `initialize()`. The lease decides. A refusal is
   `denied-access: output-owned` and the session is closed; nothing is written
   and no other path is tried.
4. Bind the session in process (`createAgentBinding`) and make it the
   workspace's subject. Session-bound operations are then dispatched to it
   locally, through the same function.

**A standalone owner publishes no descriptor in #11.** Its session is private to
the process that opened it, as a one-shot CLI call or an MCP server's own
session. Another agent sees `owner-required`. If that agent also opens a
standalone owner, the lease refuses it with `denied-access: output-owned`.
Sharing a standalone owner would add the `schedules` effect and a listener to a
`load-config` operation; no criterion of #11 needs it.

**Race.** A host and a standalone opener that start at once both see no
descriptor, and both reach `initialize()`. Exactly one acquires the lease. The
other fails `output-owned`, whichever it is. This is the lease's existing
semantics. It is tested as a race (§5), with the namespace and symlink residuals
of §6.

`session.open` and its loader live in `src/agent/standalone.js`. `workspace.js`
loads that module with a dynamic `import()` only when `session.open` is
dispatched, so the attach and discover import graphs stay free of
`api/project.js`.

### 3.11 `discover`

`discover` reports what can be observed without executing anything. Input:
`{ include: subset of [versions, hosts, roots, config-files, artifacts, owners] }`.

| Fact           | Source                                                                                                                 | Label                                                                                                                                    |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `versions`     | `package.json` of the installed `@pandamstyle/*` packages, read as JSON                                                | observed                                                                                                                                 |
| `hosts`        | Dependencies in the project's `package.json`; presence of `vite.config.*`, `rsbuild.config.*`, `next.config.*`         | observed                                                                                                                                 |
| `config-files` | Path, size and SHA-256 of `pandamstyle.config.*` and of the host config files; read as bytes, never parsed as code     | observed; contents not interpreted                                                                                                       |
| `roots`        | Not observable without executing the config                                                                            | `unknown`, reason `requires-config`; available through an attached owner                                                                 |
| `artifacts`    | `.pandamstyle/` (the default `outDir`) and its state file: `generationId` and the publishing session's identity (§1.4) | observed on disk; `freshness: 'unverified'`, reason `owner-absent`, or `owner-attached` with the live owner's `sessionId` for comparison |
| `owners`       | Descriptors for `projectDir` and its ancestors: `rootDir`, `outDir`, `host`, `createdAt`                               | `advertised`, unverified; `discover` does not connect                                                                                    |

`discover` imports no project module and starts no session (A9). Its effects are
`reads-sources`, `reads-generated`, `computes` and the new
`reads-owner-descriptors` (§3.12). A config at a non-default `outDir` makes the
`artifacts` fact `unknown`, reason `requires-config`. `discover` never guesses.

Live facts (diagnostics, current revision, design-system identity) are never in
`discover`. They come from session-bound operations, which return
`owner-required` without an owner. That is deliverable 6: observable freshness
is labelled, and live operations need an owner.

### 3.12 Outcomes, reasons and registry amendments

**A ninth outcome, `owner-required`.** Its meaning: no owner can serve this live
operation now. Its retry hint is `after-refresh`. Its code is the new
`PMS_OWNER_REQUIRED` in `AgentCodes` (`envelope.js`, off the session path).

Why not the pre-written `unsupported-capability: owner-absent` (B8, A15):

- `unsupported-capability` means "not available in this build or binding", with
  retry `never`. An agent following that hint would give up on an operation that
  works as soon as the host starts. Worse, it might treat the project as
  unsupported.
- The agent's correct next actions are specific: start the host, attach again
  later, or ask for standalone ownership explicitly. No existing outcome names
  them.
- #11 and the plan name the outcome `owner-required`.

The outcome set is closed and versioned with the registry. Adding one is
additive, and the agent protocol is not exported yet (AG-01.1 §3.1), so no
consumer breaks. PR 1 amends AG-01.1 §3.6 ("There are 8 outcomes") in the same
change, as AG-01.2 amended D1.

**Reasons, closed:**

| Outcome                  | Reason                                                        | When                                                                                         | Produced by |
| ------------------------ | ------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ----------- |
| `owner-required`         | `owner-absent`                                                | No usable descriptor for the project, or no usable runtime directory                         | client      |
| `owner-required`         | `owner-unreachable`                                           | A descriptor exists, the endpoint refuses or is missing (dead owner)                         | client      |
| `owner-required`         | `descriptor-invalid`                                          | A descriptor fails its schema, its name or its endpoint check                                | client      |
| `owner-required`         | `owner-closed`                                                | The connection closed, or the owner is shutting down                                         | both        |
| `owner-required`         | `owner-busy`                                                  | The owner's connection limit is reached                                                      | owner       |
| `stale-revision`         | `descriptor-stale`                                            | `keyId` does not match the key, or the proved session differs from the descriptor            | client      |
| `stale-revision`         | `session-changed`                                             | A request carries a revision of a session that was replaced on reconnect                     | client      |
| `denied-access`          | `authentication-failed`                                       | The owner rejected the client's proof                                                        | owner       |
| `denied-access`          | `endpoint-unauthenticated`                                    | The endpoint failed to prove the key                                                         | client      |
| `denied-access`          | `owner-present`                                               | `session.open` while an owner is attachable                                                  | client      |
| `denied-access`          | `output-owned`                                                | `session.open` lost the lease (existing reason)                                              | client      |
| `unsupported-capability` | `protocol-version`                                            | No common bridge or protocol version                                                         | both        |
| `unsupported-capability` | `anchoring-unavailable`                                       | No anchored runtime directory on this platform; `failure.capability: 'feature:owner-bridge'` | both        |
| `invalid-input`          | `owner-ambiguous`                                             | Several owners match and the input does not choose                                           | client      |
| `invalid-input`          | `malformed-handshake`, `malformed-frame`, `request-too-large` | A non-compliant peer (never produced by a compliant client)                                  | owner       |
| `internal-error`         | `owner-protocol-error`                                        | An authenticated owner sent an invalid or oversized frame                                    | client      |

`denied-access` is used only for authentication and ownership decisions, never
for a connection failure (A15).

**Registry amendments** (owner #11, reviewed with their tests):

- A new effect kind, `reads-owner-descriptors`: reads the runtime directory's
  descriptors and keys, never writes them. It is allowed under `consult`.
- `owner-required` with its reasons joins the universal contracts of every
  `binding: 'session'` entry, because the workspace binding can return it for
  any of them.
- `session.attach`: becomes `implemented`. Input as in §3.9. Effects
  `session-state: binds-client` and `reads-owner-descriptors`. The
  `reads-generated` effect is removed: attach reads no artifact. Errors as in
  the table above.
- `session.open`: `planned` → `implemented` in the second PR (§7). Effects add
  `reads-owner-descriptors`; errors add `denied-access: owner-present` and
  `unsupported-capability: anchoring-unavailable`. Its output keeps
  `RECEIPT_IDENTITIES`.
- `discover`: `planned` → `implemented` in the second PR. Output: the facts of
  §3.11 with their labels. The `unsupported-capability: owner-absent` contract
  is removed: `discover` succeeds without an owner.
- `src/agent/generated/operations.d.ts` is regenerated.

### 3.13 Alternatives considered for the descriptor

| Alternative                                       | Why not                                                                                                                                                                                                                              |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `node_modules/.cache/pandamstyle/`                | Advances the revision under `roots: ['.']` (B3, P3), is agent-writable by any process that can write the project, and follows the project into containers and copies                                                                 |

### 3.14 AG-13.1 transport requirements

| Requirement                      | How the bridge meets it                                                                                                                              |
| -------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| T1 One machine response channel  | One frame per request, carrying exactly one AG-01.1 envelope. Error frames become envelopes on the client side (§3.6)                                |
| T2 No human mode                 | The bridge has no text mode, prompt or TTY behavior                                                                                                  |
| T3 Structured bootstrap failures | Attach and open failures are envelopes with closed reasons (§3.12); `session.open` keeps AG-01.1's `stage: bootstrap` contracts                      |
| T4 Separate, bounded logs        | The bridge writes no log. A start refusal is returned to the host as a value; the host's own logging is #14–#16's                                    |
| T5 No host human channels        | The bridge serializes envelopes from `binding.dispatch` only; it never reads host output or `PmsError.message`                                       |
| T7 Reads never act               | `discover` and `session.attach` import no project module, stage nothing and start no watcher (§3.9, §3.11)                                           |
| T8 No browser client             | The bridge is a local socket; no page is involved                                                                                                    |
| T9 Envelope off inherited stdio  | The bridge is its own channel, never stdout or stderr                                                                                                |
| T10 Packaging                    | No dependency is added: `node:net`, `node:crypto` and `node:fs` only. Nothing enters `@pandamstyle/core` or the host packages' runtime closure       |
| T12 Inventory every new surface  | The runtime files, the descriptor format and the entry point are inventoried with the published entry that exposes them (§7). PR 1 publishes nothing |

T6 (the replacement map) and T11 (structured explanations) are unaffected: the
bridge forwards envelopes unchanged.

## 6. Self-attack: how this design could be wrong

- **A same-uid process reads the key.** True by design (§2). The note does not
  claim otherwise. With a write grant enabled on the bridge, any process of that
  uid can publish. Mitigation: the default is `consult`, and enabling more is
  host configuration (§3.7).
- **The directory check is not the kernel's actual rule on some system**, for
  example a filesystem that ignores modes. The `fstat` check would pass on a
  mode it cannot enforce. The handshake remains a second barrier. PR 1 supports
  Linux only, where `$XDG_RUNTIME_DIR` is `tmpfs` (S8). No second-uid probe was
  possible here; a CI test with a second user is a follow-up.
- **Network namespaces (unverified).** An owner in one container and an agent in
  another, sharing a bind-mounted project, have different abstract-socket
  namespaces and probably different runtime directories. The agent sees
  `owner-required`. If it then opens a standalone owner, the lease cannot see
  the other owner and two writers exist. `discover` states that an absent owner
  does not prove that no writer exists. Fixing this requires a filesystem-level
  lease, which changes the lease's semantics and is a follow-up (§7).
- **The symlink split of the lease (B2).** The bridge name uses the session's
  canonical `outDir`, the lease key, so it inherits the split: two owners, two
  names, two descriptors for one physical directory. Each attach still reaches a
  real owner; the defect is the lease's. Follow-up (§7).
- **Stale foreign entries accumulate** in the runtime directory: three files per
  crashed owner whose name never restarts. They cost a failed `connect` per
  attach and are cleared at logout. A client never deletes them (§3.4).
- **Squatting `/tmp/pandamstyle-<uid>`** by another uid denies the bridge where
  `$XDG_RUNTIME_DIR` is unset. It grants nothing (§3.3).
- **Two-file race at owner restart.** The client may read a new descriptor and
  an old key, or the reverse. `keyId` turns that into `descriptor-stale`, and
  the client retries once. A third interleaving is reported, not looped.
- **Host misorders shutdown** (`session.close()` before `bridge.close()`). The
  bridge answers `owner-required: owner-closed` from the binding's revoked state
  (§3.10). A request already inside `binding.dispatch` when the session closes
  can still return the binding's own `stale-revision: session-closed` or
  `denied-access: revoked`. That window is narrow. The structural ordering
  assertion of the test host, and each host's own test in #14–#16, cover it.
- **An authenticated owner returns a hostile envelope.** Only a same-uid process
  can be an authenticated owner. The client bounds the frame and checks
  `protocol` and shape, nothing more. Version skew (§3.8) means the client
  cannot fully validate an owner's envelope against its own registry.
- **Denial of service by an authenticated client.** It can hold 32 connections
  and keep the session queue busy with expensive `check` calls. Same uid, and
  fairness is AG-10.1. A slow handshake is bounded by the 2-second deadline.
- **`JSON.parse` on deeply nested input** within 65 792 bytes can throw a
  `RangeError`. It is caught and answered `malformed-frame`, then the connection
  is closed. Depth 16 is enforced afterwards by `snapshotRequest`.
- **The model is not the code.** P6 exercised a 200-line model, not PR 1. Every
  model case becomes a test (§5).
- **`owner-required` as a ninth outcome** may be judged scope growth on
  AG-01.1's closed set. It is required by #11's text and by A15. The alternative
  mapping would carry a wrong retry hint (§3.12).
- **Standalone without a descriptor** may be judged too narrow for long-lived
  MCP sessions. A second agent cannot attach to an MCP server's standalone
  owner. That is consistent and safe (the lease refuses a second writer).
  Sharing it is a later need, not a criterion of #11.
